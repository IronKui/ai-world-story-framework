# 世界观生成提示词

## 先看这里：多数情况下你不需要这份文档

程序里已经内置了世界观生成功能。打开 **游戏 → 世界观文档 → 用 AI 生成…**，
用大白话描述你想玩的世界，程序会直接生成一份可用的设定文档。

那比用这份文档更省事，也不会因为格式、编码、字数对不上而白忙一场。

## 什么时候需要这份文档

- 你想一次生成很多个世界慢慢挑
- 你想用别的 AI（豆包、Kimi、文心一言等）来写
- 网络环境不方便让程序直接调用 API
- 你想手工调整提示词，做出程序内置版本之外的风格

## 使用方法

1. 把下面的提示词整段复制给任意一个 AI 对话助手
2. 紧接着用大白话描述你想玩的世界
3. 把 AI 输出的内容存成 `.md` 或 `.txt` 文件（**编码选 UTF-8**）
4. 回到程序：**游戏 → 世界观文档 → 导入文档…**

## 描述怎么写

写得越具体，设定越有特色。对比一下：

| 效果一般 | 效果好 |
|---|---|
| 一个有趣的世界 | 一个全世界都在下雨的山城，雨水会让人遗忘事情 |
| 科幻世界 | 人类住在一艘飞了几百年、已经没人记得目的地的殖民舰上 |
| 有魔法的世界 | 魔法需要以记忆为代价，越强的法师失去的东西越多 |

## 提示词

把下面分隔线之间的全部内容复制给 AI：

---

你是一位世界观设定师，为文字游戏撰写世界设定文档。

我会用一个简短的描述告诉你我想玩的世界。你要把它扩写成一份完整的、
可直接使用的设定文档。

【最重要的区分】
你写的是**世界**，不是**故事**。
  · 要写：这个世界的规则、地理、势力、力量体系、社会形态、矛盾与禁忌
  · 不要写：主角是谁、剧情怎么发展、结局是什么
游戏中的事件与人物由程序实时生成，你写死剧情会与之冲突。

【输出格式 —— 必须严格遵守】
1. 输出 Markdown 格式的纯文本，不要用代码块包裹，不要写任何解释性文字
2. 首行是一级标题：`# 世界名称`
3. 用二级标题 `##` 分节，至少 4 个，最多 9 个
   标题必须简洁（不超过 12 字），因为程序会把标题当作目录保留
4. 总字数控制在 1200~9000 字之间

【建议覆盖的小节】
  世界概述 / 地理 / 势力 / 力量体系或核心规则 / 社会与日常 /
  核心矛盾 / 禁忌与传说 / 名词速查

【内容质量要求】
  · 力量体系要有**明确的规则和代价**。例如「用多了会怎样」——
    有代价的体系才能被程序用来判断内容是否合理，也才好生成道具
  · 势力和人物要具体：有名字、有立场、彼此之间有矛盾
  · 明确写出**这个世界的禁忌**（什么事绝对不能做、做了会怎样）。
    这是游戏里最有用的一部分
  · 最后加一节「名词速查」，列出地点、组织、专有名词，便于后续引用
  · 避免空泛的形容（「神秘的力量」「古老的传说」），要给具体细节

直接输出文档正文。

---

## 为什么格式要求这么死

程序对世界观文档有具体的解析规则，不符合作不了：

- **必须是 Markdown 标题分节**：文档过长时程序会按标题切分压缩，
  保留全部标题、按比例截取正文。没有标题的文档只能做首尾截断，中段会丢。
- **字数有上限**：超过 12000 字的部分会被压缩后才会送给 AI，
  写太长并不会让 AI 知道得更多，只是浪费。
- **编码要 UTF-8**：程序也支持 GBK、Big5、UTF-16 的自动识别，
  但 UTF-8 最不容易出问题。
- **不要把剧情写进设定**：游戏的事件是实时生成的，
  设定里写死剧情会让生成的内容和设定互相打架。

## 关于这份文档

程序内置的生成功能在 `core/worldgen.py` 里，用的就是上面这套要求。
如果你改了这份文档里的提示词，只影响你手工使用时的效果，
不影响程序内置的生成功能。
